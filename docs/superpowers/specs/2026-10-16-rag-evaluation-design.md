# RAG 检索首轮评测设计

依据用户提供的 `rag-evaluation-system.md`，先检索、后生成；Agent 三层评测另行执行。本轮保留 IEEE 英文知识库，以 15 组中英文等义问题（30 条查询）检查跨语言表现。用户已授权在无须更换语料时直接开始。

- 检索语料使用现有全部 966 个父块；现有 2737 个子块及 Chroma 索引只读复用，不重嵌入。
- 数据采用 corpus.jsonl、queries.jsonl、qrels.jsonl；父块是评分单位。额外保存证据摘录、参考答案和来源，标注为来源核验的 Agent 草稿，不称人工黄金集。
- B1 向量；B2 向量+BM25+RRF；B3 B2+原问题重排；B4 B3+Multi-Query/JEV。保留现有术语扩展，固定子路召回30、融合60、重排30、父块输出5，计算 @1/@3/@5。
- 语料保持完整，不只拿有标注的文档建立容易的子集。无关父块仍作为干扰项。
- 基线导出逐问题排名和实际失败/降级原因。B1/B2/B3可以复用相同的原问题召回中间结果，不能据此比较它们的独立端到端延迟。B4调用现有真实链路，禁止假造候选或判定。
- EvalScope 原生自定义 benchmark 负责统一调度对导出结果的回放、分语言评分和报告；自定义 scorer 调用 MTEB 官方 retrieval_metrics，不重写指标公式。回放输出明确标识为真实检索结果的回放，不冒充新的模型生成。
- 首轮只评检索，不生成业务答案，不运行 RAGAS 生成指标。参考答案及上下文为后续 RAGAS 留接口。
- 应用环境不升级；框架依赖安装到项目内隔离的 .venv-evaluation。既有缓存不清空，实验不读取 Redis 最终结果缓存。
- 语料/索引/配置/数据集哈希写入 manifest；绝不输出凭据。所有源文件按 UTF-8 读取，Windows 运行用 -X utf8，拒绝包含替换字符的查询。
- 标签来自原文的明确支持段落，暂未人工穷尽所有等价证据；分数是试跑集、草稿标注下的诊断结果，不能作为最终简历指标。

完成条件：生成可追溯数据集；实际尝试四组检索；EvalScope/MTEB产出分语言指标和失败记录；说明不能完成的阶段及其具体原因。
