# 投稿咨询助手：本地 React＋FastAPI 聊天工作台设计

日期：2026-10-22。状态：已实现并离线验收；291项后端及15项前端测试通过。独立审查收到的问题已修复，但额度限制导致未取得最终完整独立结论，详见实施进度。

## 1. 目标和已确认范围

将已有投稿咨询 Agent 接入可本地运行的聊天工作台，方便日常使用、观察路由与证据，以及项目演示。复用现有 LangGraph、工具、记忆、知识检索和可选 Redis，不另建一套 Agent。

用户已经确认：

- React＋Vite 前端，FastAPI 后端；第一版为本地单用户。
- 左侧会话列表，中间聊天区，右侧可折叠的证据与运行状态。
- 接入先前验证较好的 G6 业务提示＋新清晰度 prompt；不采用背景误选实验中退步的四类补充示例。
- 展示真实阶段和最终回答，不展示内部思维链。
- 不包含登录、知识库上传、复杂管理后台。

不在本次范围：云端托管、多用户授权系统、向量库重建、重新付费评测、修改业务分类阈值、继续调优 C03 等类别、模型 token 级流式改造、自动重试付费请求、历史数据清空。

## 2. 技术选择

采用 React＋TypeScript＋Vite 的独立 `frontend/` 和 FastAPI API 薄层。业务执行仍由 `ChatService` 与 `build_chat_graph()` 负责，服务层只管理入口、任务生命周期和公开视图。

不采用仅静态模拟页面：需要真实会话历史、证据与已有 Agent 接口。暂不采用多用户完整管理系统：本次使用场景是本机单用户，认证和管理功能不进入第一版。前后端开发分离，打包后可由 FastAPI 托管前端静态文件，从而提供同源访问。

默认后端仅监听 `127.0.0.1:8000`，开发前端为 `127.0.0.1:5173`，通过 Vite 代理 `/api`。不使用云托管，不将项目源目录作为静态目录。

## 3. 将验证过的提示词接入正式运行时

### 3.1 采用的版本

建立明确命名的稳定提示配置 `routing-g6-clarity-v3`：

- 业务分类：G6 的简短类别定义、固定正反例及公共规则。
- 清晰度：`evaluation/agent/clarity-probes/20261022-paired-01` 候选版的完整定义和示例。
- 状态：原样传入最近五轮完整用户问题和最终回答，不含工具轨迹或专业 Agent 私有执行记录。
- 阈值保持清晰度 0.75、业务相关性 0.8，6/5 分批方式保持不变。
- 不包含 `business_probe.CONTRASTS` 的任何新增示例，也不采用此前整体扩展边界组。

稳定定义放入 `src/submission_assistant/intent/` 下的正式模块，不能由产品代码导入 `evaluation/`。CLI 和 Web 的生产构建入口显式选用稳定配置；旧 baseline、few-shot-v2 仍可显式选择用于兼容和诊断。避免悄悄改变旧评测构造器的默认语义，不改历史冻结请求和分数。

用已保存的候选请求做离线逐字段对比，确保正式配置与经验证版本一致，而不是重新手写一个相似版本。此前实验成绩仍只代表对应样本，不宣称线上准确率。

### 3.2 路由服务配置

当前本地 `.env` 的路由 provider/model 仍为旧值，之前评测通过单独覆盖使用 Decisions。正式入口应使用已验证的：

- `JEV_PROVIDER=decisions`
- `JEV_BASE_URL=https://api.perplexity.ai/v1/decisions`
- `JEV_MODEL=pplx-decider-flash-v1.2`

实施时仅校准上述非敏感配置与必要的提示版本项；保留既有 API key、模型生成配置、Redis、知识库与其他用户设置。不得打印密钥、将密钥写入浏览器配置、将 `.env` 作为静态资源或放进报告。

## 4. 页面与交互

### 4.1 左栏：会话

- 新建会话、会话列表、切换并恢复完整公开对话。
- 默认标题为“新会话”，首条提问后用截短文本生成标题，不额外调用模型。
- 第一版不提供清空数据库或批量删除功能。

### 4.2 中栏：聊天

- 欢迎说明与少量投稿咨询提问建议，不冒充实时政策答案。
- 用户和助手消息、Markdown 展示、代码复制、发送中与失败状态。
- 输入框支持 Enter 发送、Shift＋Enter 换行；空白内容不能发送。
- 同一会话执行中不能重复提交另一轮；重复点击不能产生多次工具执行。
- 服务失败显示失败，部分完成显示未完成事项，不伪装成完整回答。
- Markdown 不启用原始 HTML；链接只允许安全的 HTTP/HTTPS 地址。

### 4.3 右栏：证据与状态

- 展示实际选中的业务类别和 Agent，不根据前端关键词猜测。
- 证据展示标题、来源链接、页码或章节、有限摘录。没有证据就明确显示缺少证据，不生成假引用。
- 本地文献未提供安全下载端点时，只显示标题、页码，不暴露任意磁盘路径。
- 公开状态包括阶段、角色、当前步数、剩余步数、工具调用次数、耗时及退出原因；只展示后端确实提供的字段。
- 不展示系统提示词、完整上下文、内部思维链、原始工具参数、密钥和 Agent 私有记忆。
- 小屏时会话栏与证据栏折叠；浅色、中性底色、蓝色强调，优先可读性，不引入无关装饰素材。

## 5. 后端结构与生命周期

### 5.1 服务工厂

从已有 `scripts/chat.py` 整理可复用的构建逻辑，供 CLI 与 FastAPI 使用：配置、路由识别器、生成模型路由、知识后端、记忆管理、维护任务和可选 Redis。保留现有职责与异常行为，不为网页另写一套 RAG 或记忆逻辑。

提供明确的 demo/live 启动模式：

- demo 不调用外部模型，界面醒目标识为离线演示，不将演示内容当真实政策结论。
- live 读取后端本地配置；启动只检查本地配置与依赖，不自动发起付费问答或索引构建。用户发送问题时才进入真实执行。
- 不因 live 配置错误而悄悄切到 demo。模型配置、知识索引不可用与 Redis 降级分别报告。

FastAPI 生命周期统一创建和关闭服务；先停止接收任务，再结束或取消受管任务，完成记忆任务收尾，最后关闭 SQLite、HTTP client 和 Redis。第一版只支持单 worker，防止进程内任务映射被当作跨进程队列。

### 5.2 数据边界

后端绑定可信本地身份，前端不能提交或覆盖 `user_id`。会话 ID 由后端创建，所有读取、发送和状态请求都检查该身份下的会话归属。

对话、最终回答及正式结果仍由现有 MemoryManager/SQLite 持久化。会话标题和空会话可使用新增元数据表，不重写、删除或迁移已有原文。已有本地身份的历史会话可通过公开会话视图恢复，不读取其他身份的记录。

同一会话同一时刻最多一个运行中的轮次，服务最多允许两个会话任务同时运行；不隐式排队无限任务。超过限制明确返回忙碌状态。Agent 内部已设计的专业角色协作不因此被改为前端串行模拟。

## 6. API 约定

| 接口 | 职责 |
|---|---|
| `GET /api/health` | 服务模式、已选提示版本和依赖配置状态；不返回密钥或远程错误原文 |
| `POST /api/conversations` | 创建属于可信本地身份的新会话 |
| `GET /api/conversations` | 获取会话摘要列表 |
| `GET /api/conversations/{id}` | 获取公开问答、轮次状态及对应公开结果 |
| `POST /api/conversations/{id}/turns` | 校验消息和幂等轮次 ID，启动一次受管任务，返回轮次标识 |
| `GET /api/conversations/{id}/turns/{turn_id}` | 获取公开任务状态及已完成结果，支持刷新恢复 |
| `GET /api/conversations/{id}/turns/{turn_id}/events` | SSE 订阅该轮阶段与最终结果；订阅本身绝不重新执行 Agent |

发送体只接受消息和客户端生成的随机 `turn_id`（用于幂等），身份与会话归属由后端决定；拒绝额外字段。沿用现有非空与长度限制，不因网页再引入更窄的隐性截断。

相同 `turn_id`＋相同消息：已完成则返回已保存结果，运行中返回已有轮次状态，不重复执行。相同 ID 对应不同消息返回冲突。未知会话/轮次返回404，非法请求422，同会话冲突409，服务忙碌429，配置或上游不可用使用脱敏错误状态。

## 7. 进度与断线处理

先以 POST 创建任务，再由 GET SSE 订阅，避免刷新或 EventSource 重连触发新的付费任务。

展示真实图执行阶段：接收、路由、角色执行、汇总、完成/部分完成/失败。可从图节点进度及运行时已写入的状态中提取公开字段，不能将整份图状态或私有记录直接发到浏览器。

当前模型接口返回完整消息，第一版提供阶段事件＋最终回答；不承诺 token 流式，也不把已完成的整段回答拆字模拟模型输出。最终结果在持久化完成后通知浏览器。

浏览器断线不自动重新生成；任务继续受后端管理，可通过状态端点恢复。服务重启后，无法恢复的运行中任务明确显示为中断，不自动重放工具；用户可以显式发起新轮次。刷新页面不能丢失已保存的公开对话。

## 8. 本地访问安全

- 默认仅本机回环地址，不直接暴露公网；如需远程或多用户访问，必须另行设计身份与部署。
- 开发态使用同源代理；生产打包同源托管。写接口核对允许的 Origin/Host，不配置任意来源跨域放行。
- 只托管前端构建产物，不提供任意项目文件下载；没有数据库、`.env`、报告原始配置或工作区文件浏览接口。
- 前端不包含 API key、模型后端凭证或可任意覆盖后端模型 URL 的设置。
- 公开错误不包含远程响应正文、堆栈、绝对路径或凭证；服务端必要日志同样脱敏。

## 9. 验收

1. 正式稳定提示生成的请求与已验证的 G6＋新清晰度冻结请求一致；失败的背景补充示例未接入。
2. 离线测试验证路由提示选择、API 校验、会话归属、幂等、同会话并发保护、SSE 重连不重放、错误与部分结果展示。
3. 后端测试使用受控假外部接口，不产生模型费用。原项目全套测试仍需运行，出现失败如实列出，不仅验证新增文件。
4. 前端类型检查、生产构建通过；界面检查覆盖新建/切换会话、发送、运行状态、引用、错误、刷新恢复和窄屏。
5. 真实模型端到端冒烟若需要，另行明确调用范围；开发和浏览器验收默认使用有显著标识的 demo，不自动再次跑付费评测。
6. 交付本地启动方式、访问地址、demo/live 区别及已知限制；保留原数据库、索引、评测结果和 API key。
