## 1. 目标与总体选择

实际目录面向开发者，按代码、系统资源、知识库、记忆和运行文件组织；虚拟目录面向 Agent，按四类访问区域组织。采用统一虚拟路径与后端映射，不暴露整个项目目录，不要求操作系统级挂载，也不要求虚拟与实际目录同构。

四类区域为实例专属私有区、授权共享区、系统内置资源、授权外部挂载。公共只指当前授权用户／会话范围，不是跨用户公共。每个 Agent 仅有私有瞬时记忆，公共短期与长期由系统 MemoryManager 管理；不增设独立黑板。

## 3. Agent 的虚拟目录

```text
/
├── private/
│   ├── scratch/
│   ├── tool_results/
│   └── memory/
├── shared/
│   ├── conversation/
│   │   ├── inputs/
│   │   ├── evidence/
│   │   ├── agent_results/
│   │   ├── outputs/
│   │   └── memory/
│   └── user/
│       └── memory/
├── system/
│   ├── skills/
│   ├── templates/
│   └── manuals/
└── mounts/                           # 第一版无外部接入
```

用户、会话、轮次和实例身份由后台运行身份绑定；不允许模型通过更改路径或提交另一个 user_id 切换权限。相同 `/private/` 在不同实例中映射到不同范围；同会话的授权实例共享 `/shared/conversation/`。Agent 不看见磁盘根目录、配置密钥、数据库文件和其他用户的命名空间。

| 虚拟入口 | 后端 | 访问边界 |
|---|---|---|
| `/private/scratch/` | 本实例 runtime 临时目录 | 当前实例读写 |
| `/private/tool_results/` | 本实例 memory/blobs | 框架保存原文，Agent 受控读取 |
| `/private/memory/` | MemoryManager → SQL | 本实例瞬时记忆视图 |
| `/shared/conversation/` | 会话共享文件与 MemoryManager 公共短期 | 读取授权内容，发布自己的产物 |
| `/shared/user/memory/` | MemoryManager 公共长期 → SQL | 读取有效画像，不能直接修改 |
| `/system/` | resources | Agent 只读，系统维护 |
| `/mounts/` | 外部适配器 | 源系统权限、默认只读、独立超时与凭证边界 |

memory 路径是受控视图，不要求每条消息保存成 Markdown 文件，也不提供任意数据库读写。瞬时记录、摘要和状态仍经 MemoryManager 更新。正式资源的具体访问工具将在工具设计阶段定义，不因为目录存在就自动授予读写或执行能力。

## 4. Skill、知识库与记忆

每个 Skill 位于 `resources/skills/{英文名称}/SKILL.md`，包含元数据和核心指令；references、templates、scripts 是可选第三层，不建立无内容的必备目录。系统脚本只读不等于获准执行，执行必须经过工具权限与校验。六份正文目前仍是设计文档中的草案，本文不创建运行时 Skill 文件。

Chroma 与 SQL 是独立职责的后端，不作为数据库文件暴露给 Agent；独立不要求部署在不同机器或容器。RAG 工具内部使用双路召回、RRF、重排和父块回溯，向 Agent 返回正文与出处。官方知识库不必包装成外部挂载，也不直接成为用户画像。

MemoryManager 按 ID、轮次、时间与授权范围读取记忆，初期不要求走 RAG。PromptManager 默认组装相关有效长期记忆、当前会话历史摘要及最近五轮问答；更早原文和协作结果可以按需读取。

SQL 保存结构化消息和元数据；大型结果正文保存为文件，通过稳定 artifact_id 关联。原文从保存时就与 runtime 临时文件分开，不先放在待删除目录中再依赖结束时补救。文件形式角色产物与 SQL 发布记录以引用连接，不重复维护两套权威全文。

## 5. 管理器职责

- WorkspaceManager：虚拟路径映射、文件权限、实例临时目录生命周期、共享产物发布、临时文件回收与文件引用解析。不使用 WorktreeManager 命名，以免与 Git worktree 混淆。
- MemoryManager：消息、状态、原文引用、摘要、画像、版本、压缩与封存；决定哪些内容作为记忆读取，不替代文件访问权限检查。
- RAG 模块：知识库构建、检索与证据定位，不让 Agent 直接编辑 Chroma 索引。
- PromptManager：读取一致记忆快照和授权资源，组装输入与检查预算，不持久化记忆。

共享区用户原件默认只读。Agent 仅发布自己的结果，不能覆盖其他实例结果、直接改用户画像或系统资源。并发发布按所有者与版本处理，不以最后写入覆盖作为冲突解决。文件落盘与元数据发布必须确保没有悬空引用，失败时保留来源，具体事务／发布协议在实施计划中细化。

## 6. 私人空间生命周期

私人活跃空间绑定 agent_run_id，不绑定角色名称或整个聊天会话。每次实例执行建立独立空间；等待工具、协作或用户补充属于暂停，不是结束。

```text
停止新增执行
→ 等待或取消工具、后台压缩任务
→ 确认执行原文持久化与封存成功
→ 确认必要正式产物已发布、引用有效
→ 撤销本实例私人活跃访问
→ 回收 runtime 临时工作目录
```

草稿与可重建缓存可回收；消息、工具原文与压缩来源保存在 SQL／memory/blobs 的私有档案；正式证据和交付物保存在会话共享区。撤销活跃目录不删除唯一原文，不使私有记录自动公开；框架仍可按授权用于追溯。稳定 artifact_id 由后台解析物理位置，不能只引用会随回收失效的绝对临时路径。

归档／发布失败或仍有后台读者时不能清理。取消、中断与进程异常不能误标为成功；收尾需要可重试且不重复发布。保留期限、容量配额、显式删除和备份处理另定，不默认无限保存，也不默默删除来源。

## 7. 实施前验收要求与边界

1. 不同用户、会话和实例不能越权访问；路径穿越、符号链接及 Windows junction 不能逃逸映射范围。
2. Agent 不可读取 .env、直接数据库文件、索引文件或其他实例原文。
3. 同角色并发运行不会相互覆盖；同会话正式结果按 owner／版本发布。
4. runtime 回收后原文和共享产物引用仍可解析，失败及后台任务未结束时不清理。
5. SQL 记忆视图与共享文件保持权限和引用一致，无重复黑板或第二套权威记录。
6. 原文保留、三级记忆、70% 异步压缩与缓存友好 Prompt 规则继续遵循既有记忆设计。

本次只保存设计与入口，不创建数据库、运行目录或 Skill，不迁移／删除文件，不安装依赖，不调用模型。下一阶段为渐进式 Skill 披露设计，再讨论必须工具与特殊工具；尚不进入整个 harness 的实现。
