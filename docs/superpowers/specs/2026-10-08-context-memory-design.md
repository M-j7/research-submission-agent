# 上下文管理与三级记忆系统设计（v0.3）

日期：2026-10-08。范围：IEEE Access 投稿咨询助手的 Agent harness。

状态：设计修订稿，不代表已实现。v0.2 取消独立黑板，明确 Agent 只有私有瞬时记忆，短期和长期由系统公共区管理；v0.3 按用户最新确认，将短期输入统一为“当前会话更早问答的压缩摘要＋最近五轮原始问答”，明确记忆原文保存、Prompt 只读取组装。本文保存已确认规则；具体并发协议和存储接口仍需实施验证。本次只修订文档，不修改 Agent、RAG、数据库、模型配置或依赖。

## 1. 设计目标与决定的状态

目标：Agent 各自处理问题、调用工具，但私有过程不串扰；共同条件和正式结果可以共享；Prompt 有稳定顺序；长工具输出和长执行过程可控，压缩可追溯。

### 1.1 用户已确认或明确提出的规则

- Prompt 管理器只负责选择和组装本次输入，不负责持久化。
- 所有消息记录由 Memory 管理；保存消息不等于全部放入 Prompt，也不等于全部公开。
- 采用四类文件区域：Agent 私有工作区、任务共享工作区、外部挂载、系统内置资源。
- 取消独立黑板：直接从系统公共短期／长期记忆读取，不增加黑板存储、独立状态对象或第二套写入链路。共享工作区保存档案与共同文件，Memory 持有消息／元数据及文件引用。
- Agent 继承统一基础 Agent，仅角色提示词和工具权限不同；不要另生成一段缺乏用户依据的“分配任务”。输入为原始问题、对应意图和有权限读取的背景。
- 项目内约定：瞬时记忆对应本轮问答；短期记忆对应当前会话；长期记忆对应用户级跨会话信息。此命名是项目约定，不宣称行业有唯一分层规范。
- 第一版分配冻结为 Agent 私有瞬时记忆＋系统公共短期记忆＋系统公共长期记忆；Agent 不拥有自己的短期／长期库。公共仅对当前授权 Agent 可读，短期按会话、长期按用户隔离，不是全站公共数据。
- Agent 自进化留作未来扩展：届时按需要增加角色经验记忆，与系统用户画像分开；第一版不积累角色私有长短期经验。
- 记忆逐级沉淀：瞬时 → 短期 → 长期。长期提取来源为短期记忆，触发计数单位是该用户已完成转存的瞬时记忆次数，不是会话数或 Agent 实例数；N 可配置，未冻结数值。
- 长期画像提取回答偏好、相关长期背景和跨咨询持续要求，支持动态更新、前后矛盾处理及来源／修订备案，不盲目覆盖。
- 工具结果默认原样保存、原样组装，不对每次工具返回预先调用 LLM 精简。
- 瞬时记忆分为绝不可压缩区、一级压缩区、二级压缩区。
- 按步次保存 assistant 与 tool 消息；工具指令和结果必须配对。
- assistant 按 Schema 组织，第一版不再进一步区分普通 assistant 文本。Schema 的字段契约见第 7 节；不是已部署的 API 配置。
- 较早工具结果周期性压缩，Prompt 中目标保留最近 1～2 次完整工具交互。第一版候选默认取 2 次，具体周期尚未冻结。
- Agent 状态栏可压缩，属于二级压缩区，始终放在 Prompt 最后。
- 公共短期提供当前会话“更早问答的压缩摘要＋最近五轮原始用户／最终助手问答”，不是最近五份各自压缩的记录，也不默认加载其他会话。
- 所有压缩均依据原始记录；摘要不是唯一真相。记忆原文保存，压缩不覆盖或删除来源。本轮活跃瞬时状态结束后，其原始记录仍在原有私有范围内归档，不因结束自动公开或删除；保留期限与配额另议。
- 本次提出异步压缩：组装输入达到可用输入预算的 70% 时启动后台压缩。

### 1.2 新增工程建议，不能当成已有能力

- 快照读、追加式原始记录、版本化摘要投影、条件提交、请求边界切换。
- 每个 Agent 实例最多一个压缩任务运行；后续触发合并，不无限排队。
- 达到输入硬上限前，压缩未完成时允许受控等待；不能把超长请求硬发给模型。
- 摘要校验失败不切换视图；本轮结束时取消或等待后台任务，完成必要转存与原文归档后释放活跃状态／缓存，不释放唯一原文。
- 不自动调用外部模型验证本文，不把用户讨论授权扩大为实施授权。

### 1.3 新架构总览

```text
系统 Memory 管理器
├── 公共短期记忆：user_scope / conv_id
│   ├── 全部会话原文及其来源
│   ├── 输入视图：更早问答摘要＋最近五轮原始问答
│   └── 本轮已发布角色结果、证据、协作状态
├── 公共长期记忆：user_scope
│   └── 当前有效用户画像、来源、版本与变更备案
└── 私有瞬时记忆：user_scope / conv_id / turn_id / agent_run_id
    ├── 规范 Agent 本轮执行
    ├── 费用 Agent 本轮执行
    └── 其他实际参与者本轮执行
        ↓ 读取授权记录
Prompt 管理器：选择 → 按模板组装 → token 计数 → 不可变调用快照
        ↓
模型／工具执行：新增记录写回对应瞬时记忆
```

这是三个逻辑范围、一个统一管理边界，不要求三套物理数据库。Agent“拥有”私有瞬时状态，指记录范围和访问权限，不是每个角色各自搭建一套 Memory 服务。公共信息读取和结果发布接口足以协作，不保留一个更名后的独立黑板对象。

## 2. 范围、层级与术语

```text
用户 user
├── 长期偏好／画像：用户级，可跨会话使用
└── 会话 conversation
    ├── 第 1 轮问答 turn
    │   ├── Agent 实例 run_A
    │   │   ├── 执行第 1 步：模型响应 → 工具调用与结果
    │   │   └── 执行第 2 步：模型最终响应
    │   └── Agent 实例 run_B（需要多角色时）
    └── 第 2 轮问答 turn
```

- 一轮问答：一次用户消息到系统最终给用户的回答。内部多 Agent、多工具调用不增加用户问答轮数。
- 会话：用户新建的一条聊天，可以有多轮。用户画像属于用户，不是多个会话本身。
- 执行步次：同一 Agent 实例本轮内部的一次模型交互。一次响应可能调用多个工具，也可能直接回答而没有工具结果。
- 一组工具交互：一个 assistant 响应提出的全部工具调用，以及它们对应的返回结果。最近 1～2 次按完整工具交互组计，不按工具个数或用户问答轮数计。
- `task_id`：咨询任务／共享产物的范围。第一版可与会话对应；除非出现明确业务需要，不额外建立另一套任务编排。
- `request_id`／`turn_id`：本轮请求／问答轮次；`agent_run_id`：该角色的一次实例执行；`step_id`：该实例内部的模型交互步次。

磁盘持久化不等于长期记忆：当前会话的历史可落盘恢复，但不会因此自动作为另一会话的背景。LangGraph checkpoint 是执行恢复状态，不是用户画像，也不替代本设计的读取权限。

## 3. 管理器之间的职责

| 组件 | 职责 | 不负责什么 |
|---|---|---|
| Prompt 管理器 | 按模板和权限选择记录、按步次组装、估算输入 token、返回不可变调用快照 | 不保存记忆、不调用 LLM 总结、不修改原始消息 |
| Memory 管理器 | 按范围管理 Agent 私有瞬时、公共短期／长期，保存来源、状态和摘要，提供一致读取、转存与画像更新 | 不执行模型提出的业务工具、不将猜测直接当事实、不公开私有轨迹 |
| 压缩协调逻辑（可属于 Memory） | 调度后台摘要、校验候选、条件提交新投影 | 不直接覆盖正在使用的 Prompt，不改写工具指令 |
| Agent／工具执行框架 | 模型和工具循环、Schema 校验、权限、调用配对、预算与错误处理 | 不仅靠 Prompt 实现权限，不向其他 Agent 暴露全部私有记录 |

基础交互：先逐步保存新增记录，再按需要组装 Prompt，不是在本轮结束后把整份 Prompt 再倒进 Memory。系统提示词、工具定义、Skill 原文件由系统资源／配置管理，通过版本或引用关联，不在每次调用中重复归档全文。

压缩改变“模型看到的视图”，不覆盖压缩来源。它不是第四类记忆，也不要求一个额外的全量记忆库。

### 3.1 公区读写与快照

候选接口：读取公共会话快照、按记录 ID／范围读取旧消息、发布角色结果／证据／问题、由系统完成轮次转存和画像批次更新。接口可用服务方法或获授权工具提供，具体名称不是已部署功能。

- Agent 可以读相关公共短期和该用户长期字段，但不能任意改全局事实、画像或另一个角色的结果。
- Agent 提交结果和更新建议，Memory 校验来源、范围、所有者后写入；预算和执行状态由框架生成。
- 同轮多个 Agent 初始读取同一公共快照。需要读取稍后发布结果时，显式取得新版本，状态栏记录见过的版本。
- 一次 Prompt 组装使用固定的公共版本及私有投影版本；并发发布不能让该次组装读到半个新状态。
- 修改公共数据用版本条件提交／事务，独立角色记录按 owner 合并，不用最后写入覆盖他人结果。公共长期依用户身份隔离，即使换了 conv_id 也不能跨用户读取。
- 公共资料中的用户文本、报告和工具内容是数据，不是提升权限或改变系统规则的指令。

### 3.2 一轮完整数据流

1. 接收用户消息，为本轮建立 turn_id；该输入只保存一个权威记录，各参与 Agent 可引用，避免多角色重复计数或重复归档。
2. 读取当前会话公共短期与相关用户公共长期快照，提供必要历史作意图判断。当前意图由本轮识别产生，不直接沿用旧分类。
3. 路由到实际角色，创建各自私有瞬时记忆。原始问题、角色对应意图和授权公共背景进入组装，私有消息不得混入其他角色。
4. Agent 循环：模型响应与工具结果逐步写入私有瞬时；Prompt 组装当前投影；一级／二级压缩依本设计运行。
5. Agent 正式提交自己的结果、证据和必要 issue，写入公共短期的本轮记录。框架负责完成／失败状态；中间发布不等于整轮已成功。
6. 汇总阶段按 turn_id 读取角色结果，不读取全部私有试错。若使用模型汇总，该执行者也只有自己的本轮瞬时状态，沿用相同输入与预算规则。
7. 最终答复发布后，由系统统一提交用户／最终助手历史、事实更新、待办、稳定证据引用，并完成本轮转存标记。多角色各自完成不分别增加用户轮次计数。
8. 封存私有瞬时并完成后台收尾，保存原文档案后释放活跃状态／缓存，不删除唯一来源；用户计数达到 N 后，从公共短期批次提取公共长期画像，版本校验后提交。

取消／失败的轮次要可识别为中断，不能发布虚假的完整成功记录。本轮最终转存和计数幂等；所需来源转存失败不释放其瞬时原文。具体中断轮次是否计入 N 待细化，第一版建议仅计完成转存的有效轮次。

## 4. Prompt 模板与 KV cache

### 4.1 逻辑顺序

```text
固定部分
  1. 当前 Agent 的身份、职责、范围
  2. 行为规则、证据要求、权限边界、输出要求
  3. 基础工具简介：用途、何时使用、限制
  4. Skill 库简介：目录、描述、按需读取方法

动态部分
  5. 公共长期记忆：当前有效用户画像，不含旧版及全部变更备案
  6. 公共短期记忆：当前会话更早问答的压缩摘要＋最近五轮原始用户／最终助手问答
  7. 当前用户消息与对应意图
  8. 本 Agent 的私有执行消息：按 step_id 还原 assistant → tool
  9. 最新 Agent 状态栏
  10. 模型生成位置
```

正式工具定义通过 API 的 `tools` 字段提供，逻辑上位于固定输入部分；实际序列化由服务决定，不把工具参数 Schema 再完整复制进 system。当前消息不重复进入最近五轮；“最近五轮”不等于十条完整消息在任何情形下都一定装得下，需计算真实预算。

第 7～9 项均来自本 Agent 的私有瞬时记忆：当前输入与意图、按步次记录的 assistant／tool 轨迹、最新状态栏。分项只表示组装位置，不是独立存储组件；状态栏始终位于末尾。Memory 负责存储、更新、压缩与版本管理，Prompt 管理器只读取一致版本、按顺序组装并检查输入预算。

历史摘要保留更早但仍有效的条件、约束、关键结论、更正、未完成事项及证据引用；不再额外拼一段重复的“会话事实与旧摘要”。Memory 维护有效事实和压缩版本，Prompt 管理器只读取一致快照并组装，不临时调用 LLM 总结。记忆与最新明确更正冲突时，不沿用旧事实。事实、证据、Agent 推测分别标识。公区文件／报告按需读取，不把全量原始档案或画像变更备案自动注入。当前轮多 Agent 正式结果在协作／汇总需要时读取，不混成历史用户问答。

### 4.2 Skill 渐进披露

先给稳定的 Skill 名称与描述目录；Agent 需要时读取正文；附带参考、模板、脚本再按需读取。展开内容进入该 Agent 的工具记录，不反复动态追加到 system。Skill 不得授予超出框架允许范围的权限。

### 4.3 缓存原则与限制

- 角色文本、规则、工具定义与顺序、Skill 目录在一次 Agent run 中保持稳定。
- 普通执行尽量追加新消息，冻结历史事件的时间与 ID；最新状态在尾部追加，旧快照不回头修改。
- 状态有 revision，同一 run 最新有效 revision 为准；不是所有旧状态都永远重复传入。
- 切换摘要／滑动窗口会改变动态历史前缀，允许在明确调用边界发生。不承诺周期压缩不会影响缓存。
- 首次使用某个压缩版本的输入建立新基线，后续继续追加。异步只减少等待，并不能消除缓存失效。
- 服务方前缀缓存与应用层检索／向量缓存是不同机制；命中取决于实际模型、序列化、服务能力及指标。
- 不依赖特定供应商的 `cache_edits`，不向 Qwen 网关假定存在未核实的历史编辑能力。

## 5. 四类文件区域

2026-10-08 后续确认：本节下方树为早期候选，具体目录、虚拟映射与回收职责以 [虚拟文件系统与实际存储设计（v0.1）](2026-10-08-virtual-filesystem-design.md) 为准。私人活跃空间按实例回收，原文保存于独立持久化后端，公共记忆目录为 MemoryManager 受控视图；本文的三级记忆与压缩规则不变。

```text
workspace/
├── system/                         # 系统内置，只读、跨咨询稳定
│   ├── skills/
│   ├── templates/
│   └── role_contracts/
├── tasks/{task_id}/
│   ├── private/{agent_run_id}/     # 实例隔离
│   │   ├── scratch/
│   │   └── tool_results/
│   └── shared/
│       ├── inputs/                 # 用户原件：Agent 默认只读
│       ├── evidence/               # 正式发布、需要共同引用的证据
│       ├── agent_results/
│       ├── history/                # 完整用户会话档案
│       └── outputs/
└── mounts/                         # 用户授权外部资源，默认只读
```

这是规划树，不声称目录、挂载或访问工具已存在。

1. 私有区：中间产物、临时文件、草稿、调试记录。按实例隔离，不只按角色名隔离。其他 Agent 和普通用户界面不直接读取其内部过程；不是应用管理员绝对无法访问的加密承诺。
2. 共享区：用户材料、发布的证据、角色结果、最终报告、会话档案。共享不是所有 Agent 可任意覆盖一切；上传原件只读，结果有所有者。
3. 外部挂载：授权 Drive、Notion 等适配器，权限、只读／可写、凭证、超时、延迟和一致性边界明确；第一版无具体需求，不实现。
4. 系统区：Skill、模板和角色规则，由系统维护，Agent 只读。官方知识库也应通过受控只读服务访问，不因来源在网站就必须包装为外部挂载。

消息可以存于数据库／状态存储；四类目录不要求把每条消息都写成文件。大型结果可用私有文件后端，完整原文与其瞬时来源一起归档；活跃工作副本可在归档完成后释放。需要公开跨轮使用的发布证据转入共享区，私有原文不因此自动公开。

路径权限必须由框架检查，包括路径穿越、符号链接／Windows junction 逃逸；不得把 API 密钥放入模型可读区域。本文不要求新增数据库或 Git worktree。

## 6. 公共记忆与 Agent 私有瞬时记忆

### 6.1 取消独立黑板

以前讨论过用黑板承载最近五轮、意图、事实和共享结果；最新决定是直接由公共短期记忆提供这些记录和查询，不再额外建立黑板。删除的是重复概念和状态，不是共享协作能力。

- 公共短期拥有会话历史、五轮视图、当前有效事实、约束、进展与摘要。
- 本轮 request 元信息、角色正式结果、证据和 issue 也由公共短期管理，按 turn_id 与 owner 查询。
- 公共长期提供该用户有效画像及历史备案，由系统周期提取维护。
- 超出五轮的原始会话仍在公共档案；关键前提不因窗口滑动而消失。
- 完整文件只有一份，公区记录引用共享产物；不另复制到黑板存储。
- 公区共享不等于对所有人公开，不等于所有内容都进入每个 Agent 的 Prompt。

### 6.2 公共记录类型

| 类型 | 内容 | 发布／更新边界 |
|---|---|---|
| `request_context` | 当前问题、意图、参与角色、输入引用 | 框架写入 |
| `fact` | 用户明确提供的条件／更正，带消息来源 | Memory 统一维护；Agent 只能提议 |
| `evidence` | 必要官方原文、来源、位置、版本或日期 | 工具／Agent 发布，保留出处 |
| `result` | 角色结论、证据引用、未解决事项 | 对应 Agent 拥有，不覆盖他人结果 |
| `issue` | 缺失信息、失败、证据冲突、协助需求 | Agent／框架发布，不等于用户表达不清 |

共同外壳：`id/type/task_id/turn_id/producer/agent_run_id/revision/created_at/payload/evidence_refs/artifact_refs`。ID、所有者、时间由程序生成；读写范围由运行身份决定，不信任模型自己填写的 scope。

优先独立追加记录／发布新版本，版本替代需注明来源。并发结果由框架合并；冲突显式记录，不用最后写入覆盖结论。接口是公共记忆读取及结果／证据／问题发布，不设黑板专用库或“任意修改共享文件”工具。

### 6.3 第一版实际分配

| 记忆 | 管理范围 | Agent 权限 | 生命周期／用途 |
|---|---|---|---|
| 私有瞬时 | 某次 agent_run_id 的本轮执行 | 仅实例及授权框架／压缩器可读写 | 服务当前用户问答，必要转存后结束 |
| 公共短期 | 当前 user_scope / conv_id | 读相关快照，提交自己的正式产物／更新建议 | 多轮承接、角色结果协作、会话归档 |
| 公共长期 | 当前 user_scope | 读取相关有效字段；不能随意直接改画像 | 跨会话偏好／背景／持续要求及备案 |

Agent 没有私有短期和私有长期记忆。能读取系统公共背景，不代表角色拥有一份画像副本。正式发布是私有到公有的边界，不公布全量工具轨迹。Schema 与引用校验不能证明结论一定正确，待核验／冲突标识保留。当前稿件状态不自动变成永久用户属性。

### 6.4 自进化留作未来扩展

后续确有角色学习需求时，可加入角色私有短期候选经验／待验证改进、私有长期的已验证策略／教训。这些是“改进 Agent 做法”的经验，不是“了解用户”的画像；不能混入其他用户个人资料。

未来经验启用应有来源、评测、版本和回滚，不把模型自评或一次偶然成功直接变成规则。第一版不实现此能力，稳定方法继续由系统 Skill 提供，不为预留概念创建额外存储。

## 7. 瞬时记忆结构、步次与状态栏

### 7.1 三个处理区，不是三个存储库

```text
本轮瞬时记忆
├── 绝不可压缩区
│   ├── 本轮用户消息、意图、有效约束
│   ├── 按 step_id 保存的结构化 assistant 消息
│   └── 消息角色、顺序、工具调用 ID／名称／原始参数与配对信息
├── 一级压缩区
│   └── 按 step_id 和 tool_call_id 保存的 tool 结果正文
│       ├── 原始正文或私有文件引用
│       └── 摘要候选、有效版本和来源范围
└── 二级压缩区
    └── Agent 状态栏：计划、最近事件、环境与警告
        ├── 原始状态／事件版本
        └── 经校验的精简展示
```

结构化 assistant 原记录保持完整，第一版不再对普通 assistant 文本设置额外分类。用户／assistant 和配对元数据不可压缩的是本轮消息，不是承诺永远完整注入所有跨会话历史。系统固定规则独立于瞬时消息管理，组装时仍受保护。

### 7.2 执行步次与配对

原始记录最少有 `turn_id/agent_run_id/step_id/record_id/role/created_at`。工具调用与返回还必须有一致的 `tool_call_id`。一次响应可含多次调用；多个结果通过 ID 关联，不能仅靠返回顺序配对。

```text
用户问题
→ 第 1 步 assistant：调用 C01、C02
→ 第 1 步 tool：C01 结果、C02 结果
→ 第 2 步 assistant：调用 C03
→ 第 2 步 tool：C03 结果
→ 最新状态栏
→ 下一次模型生成
```

不同处理区只是存储／处理视图，序列化必须还原 API 要求的顺序。工具正文变为摘要时，仍是匹配该调用的 tool 消息，保留 ID。不得保留旧 assistant 调用，却删除对应 tool 消息、用一段不配对的背景文字取代。

未执行、执行中、同批未全部返回的工具交互不进入历史压缩。工具执行只认原始原生 tool-call 指令，不能从摘要重建或自动重放已执行指令。

### 7.3 assistant Schema 的初版字段契约

这是应用层逻辑契约，后续需要与配置的模型／网关对照验证，不声称已支持某个严格输出参数。

- `response_kind`：`tool_request` 或 `final`。
- `content`：可见文本／最终答复；最终答复必须由框架明确发布给用户。
- `tool_calls`：原生工具调用的 ID、名称和参数，以提供方实际响应为准，不接受普通文本中的 JSON 自行充当执行指令。
- `evidence_refs`：必要引用，若无则为空，不允许伪造。
- `status_patch`：模型可提议计划变化；完成状态、预算、工具成功等仍由程序验证后更新。

该契约不索取隐藏思维链。Schema 保证结构，不等于保证事实正确、权限正确或实际执行成功。

### 7.4 状态栏

示意字段；示例名称不表示有真实执行结果：

```yaml
agent_status:
  revision: 3
  agent_run_id: run_001
  task_plan:
    goal: 回答本 Agent 对应意图
    todo:
      - id: T01
        action: 核实相关官方要求
        status: in_progress
  recent_events:
    - event_id: E03
      tool_call_id: C03
      outcome: timeout
      duration_ms: 3000
  environment:
    phase: retrieving
    public_memory_versions_seen:
      short_term: 4
      long_term: 2
    loaded_skill_refs: []
    evidence_refs: []
    remaining_tool_calls: 3
    warnings:
      - 检索未成功，不得宣称已核实
```

程序负责真实状态、时间、耗时、资源引用、预算；模型只提议计划。状态栏不存整份工具正文，属于二级可压缩区。精简可合并已完成事项、重复事件、环境描述，但当前阻塞、待办、关键警告和真实预算不能被篡改。

## 8. 原始结果、压缩与生命周期

### 8.1 原文默认进入，不预先总结

```text
工具执行返回
→ Memory 保存结果（必要大对象可由文件后端承接）
→ Prompt 管理器尝试原样组装并计数
→ 在周期／容量触发下切换压缩展示
```

不对每次工具输出调用一次摘要 LLM。先前讨论的“每次工具默认 2,000 token 预览”不是冻结决策，已被原文优先方案替代。实际接收、落盘字节硬上限、超大单次结果处理仍必须存在，但具体数值待按工具与服务确定。

单次结果本身超出可用窗口时无法原样发给模型。兜底为按范围读取／分段摘要；保持原始记录和可查引用，并明确此次视图非全文。分段读取受本轮调用和 token 预算约束，不无限翻页。超过接收／存储硬上限时返回结构化“结果过大，请缩小范围”，而非无限下载。

### 8.2 两级压缩顺序

1. 周期检查一级区：旧的、完整结束的工具交互结果生成摘要；最近 1～2 组目标完整展示。执行次数和时间周期未定，默认候选保留 2 组。异步期间允许尚未切换的旧完整视图暂存；到硬边界前必须解决，不能承诺后台永远赶得上。
2. 容量仍紧张时处理二级区：精简状态栏。不可改写不可压缩区，不把状态摘要当事实新来源。
3. 若无可压缩内容、摘要没有节省，或不可压缩区本身超过预算，缩小任务／阶段或明确停止，不重复无限总结。

“瞬时记忆整体压缩”在本方案中只指按这两级建立更短投影，不代表对整个对象无差别总结。

### 8.3 摘要防漂移

- 原始记录追加式保存；摘要另存，与原文关联，不覆盖来源。
- 摘要保留 `summary_id/version/source_record_ids/covered_range/source_hashes/created_at/generator_version`。
- 定期从保留原文重新生成，不永远压缩上一版摘要。具体重新生成周期作为配置，不冻结未经测量的次数。
- 来源太长时分批读取并可追溯合并；不是要求一次把全部原文放进摘要模型窗口。
- 数字、路径、证据引用、约束、待办和状态变化校验；出现无来源事实、冲突或事项丢失则不提交。
- 对高风险政策／费用结论使用原始证据核验。字段校验只发现部分错误，不宣称能证明摘要语义完全正确。

工具日志优先结构化错误；需要规则解析日志时保留完整错误块和必要邻近行、合并重复进度；不默认复杂终端日志解析已存在。

### 8.4 生命周期与转存

按最新确认区分活跃状态与原文档案：本轮执行结束后，瞬时记忆不再作为活跃执行状态，但原始消息、工具结果和状态事件仍按原有私有权限保存。压缩候选、临时副本与缓存不要求长期保留。归档仍属于 Memory 管理的原始记录，不新增第四类记忆，也不将私有档案当作公共短期背景。

顺序：封存本轮 → 确认全部记忆原文已保存，必要的公开原文／证据／事实／待办转存公共短期或共享产物 → 停止新压缩任务 → 取消或等待在途任务、释放读者引用 → 释放活跃状态及可重建缓存。保存／必要转存失败时保留有关来源并标记失败，不能计作已成功沉淀，不删除唯一原文。

如果取消／进程异常，则标记中断，不把未完成状态当成功；资源清理需等运行者不再访问来源。清理只针对该 run 已验证范围，不涉及知识库原件或其他用户文件。

用户对话与最终答复保存在公共会话历史，内部执行原文保存在私有档案；保存不等于全部进入 Prompt。当前设计不因压缩、滑窗或本轮结束自动删除记忆原文；这不表示无限容量或永远保留。配额、留存期限、显式删除和备份清理另行确定，不能通过摘要替代原文保存或默默清理来源。

## 9. 70% 异步压缩：预算与触发

### 9.1 70% 的分母

令：

```text
C = 模型实际可用上下文窗口
O = 本次预留输出 token（包含提供方要求计入的输出预算）
M = 计数误差与安全余量
A = 应用配置的输入预算
B = min(A, C - O - M)
P = 本次预计完整输入 token
```

要求 `B > 0`；P 包括固定 system、工具定义、Skill 内容、会话背景、本轮 assistant/tool 消息和状态栏。不是只数工具正文，也不是“当前 Prompt 长度的 70%”。实际 tokenizer／服务计数优先；估算需留余量，不把字符数当 token。

容量触发：`P >= 0.70 * B`，开始异步压缩检查。示意：B=20,000 时，14,000 触发；这不是项目当前模型的真实配置。

周期一级检查也走同一后台协调器；具体周期未冻结。两个触发不能创建两个并发摘要任务。70% 是预警触发，不是强制删到 70%，更不是摘要完成前可无限继续生成。

### 9.2 为什么会读写不同步

- 摘要基于第 5 步生成时，第 6 步结果可能已追加。
- 摘要旧 TODO 为 pending，但实时状态已完成。
- 两个任务同时完成，旧摘要可能覆盖新摘要。
- 请求组装期间原地改列表，可能丢配对或读到半个版本。
- 本轮结束释放原文件时，后台摘要还在读取。

不能通过一个长时间锁住所有执行的方式解决：持锁等待远程 LLM 会使前台无法推进。

## 10. 建议的异步一致性协议

本节是本次新增设计，需后续实现与测试验证。

### 10.1 分离原始日志与压缩投影的版本

```text
raw_revision          # 原始日志头，新增记录就前进
projection_revision   # 当前被接受的压缩展示版本
status_revision       # 当前真实状态版本
constraints_revision  # 当前约束／必要事实的版本
```

原始记录写入后不原地修改。状态变化追加事件／新状态版本；摘要候选只生成新投影。对外逻辑原子读取可通过短锁、事务或等价不可变快照完成，选型待实施时决定。

### 10.2 快照生成候选

1. 在短临界区取固定来源快照：作用范围、截止序号、来源 ID／哈希、基准投影版本、必要约束版本。
2. 只选择已完成且不属于最近保留组的 tool 正文；二级先选择历史事件和已完成 TODO 的可合并描述。
3. 退出临界区后调用摘要模型。原始来源被本任务引用持有，不会在期间清理。
4. 摘要完成后生成候选，不直接覆盖 Memory 或当前 Prompt。

### 10.3 校验与条件提交

- 校验来源完整、作用范围正确、Schema 与引用有效、配对不变、摘要未修改保护字段、当前 run 未结束。
- 使用基准 `projection_revision` 与当前版本做条件提交（compare-and-swap／等价事务）；已有更晚投影则丢弃或重算，不能覆盖。
- **不能要求当前 raw_revision 必须等于快照版本**：正常追加的新记录应保留在截止序号之后，不能让所有后台任务因追加而永远过期。需确认被压缩的来源前缀／记录哈希未变、范围没被其他投影冲突改写。
- 新消息在 `cutoff` 之后直接拼接到候选投影，绝不由旧快照覆盖日志尾部。
- 新约束／纠正改变了摘要依赖的含义，或来源范围已失效，则重新校验／重新生成；不能只检查摘要完成得早不早。
- 第二级状态候选不能替换整份旧 status 快照：只合并它覆盖的历史事件／已完成描述，并以实时 TODO、阻塞、预算、警告重建最新状态。源状态已变且无法安全合并时，丢弃候选。
- 发布的是一个完整新投影引用；Prompt 读者只看旧版或新版，不看一半旧一半新。

### 10.4 在模型请求边界切换

已经发给模型的调用快照不可改。后台新版本就绪后，在下一次模型调用组装时选用；正在执行的工具同样不因摘要切换被重复执行。

```text
前台：追加第 5 步 → 发起调用快照 V8 → 继续等待／执行
后台：压缩固定旧范围 → 校验 → 发布投影 V9
前台：保存新增结果 → 下一次组装读取 V9 + cutoff 后的新记录 + 最新状态
```

若压缩发生在工具组尚未全返时，只压缩更早已完成组。需要追加状态栏的消息必须满足模型 API 对原生工具配对的要求，不在 assistant 调用与其 tool 返回之间任意插入不支持的角色消息。

### 10.5 去重触发与硬上限兜底

- 每个 run 最多一个在途压缩任务；新触发登记更高目标，不无限创建任务。
- 无新增可压缩来源、重复失败或候选没有实际缩短，不对同一范围持续重复调用。记录失败并受控等待、缩小范围或停止。
- 输入仍在 B 内，可继续使用一致旧视图；每次实际发送前必须重新计数。
- 预计下一次输入超过 B，停止新模型调用，等待可用候选；超时／失败则采用分段读取、明确缩小处理或终止，不能硬发超长 Prompt。
- 70% 留出的空间不保证能容纳一次巨大工具结果；单次结果接收上限及超大结果分段兜底仍独立生效。
- 限制后台任务时间、调用次数和总成本，取消传播；禁止无上限重试。
- 不设置未经讨论的第二个固定触发百分比，后续按测量配置迟滞／低水位，避免来回触发。

## 11. 系统公共短期与公共长期记忆

瞬时、短期和长期的业务范围、逐级来源与触发单位已讨论确认；存储接口、周期数值与以下具体冲突算法仍是设计，未实施。

### 11.1 系统公共短期记忆

本节为已确认短期记忆方案的正式记录，在本文件内原位维护，不另建同内容副本。公共短期承接当前会话已完成的问答；按 user_scope／conv_id 隔离，存储内容与提供给 Prompt 的视图区分如下。

#### 11.1.1 保存哪些内容

1. **全部用户问答原文**：每轮的用户问题与系统最终交付给用户的回答，附会话 ID、轮次 ID、消息 ID、角色和时间。多 Agent 协作保存系统最终答复，不把各角色的私有执行轨迹混入公共对话；全部原文保留，最近五轮只是读取窗口。
2. **五轮窗口之前的压缩摘要**：保留用户已明确的条件、已讨论问题与关键结论、用户更正、未解决问题、当前进展，以及必要证据引用。摘要区分用户确认事实、助手建议与待核验结论；纠正后的事实不与旧值同时当作当前事实。业务信息已有原文来源，摘要是精简表达，不再增加一套重复背景。
3. **必要证据与共同产物的稳定引用**：记录官方来源网址、文档位置、版本／日期（可获取时）、必要摘录，以及已经生成的检查报告或共同文件引用。需要跨轮使用的证据不能只指向随活跃执行结束而失效的临时文件；公共引用需对应获授权且实际保存的来源。不默认把全量搜索返回、重复日志或私有工具轨迹搬入公共短期。
4. **摘要追溯信息**：记录摘要覆盖轮次、来源消息 ID、版本及更新时间，以便核验、纠错和从保留原文重新生成。来源由程序关联，不由模型杜撰。

```text
公共短期记忆——按当前会话隔离
├── 全部用户问答原文及消息元数据
├── 更早问答的压缩摘要及来源信息
└── 必要证据、共同产物的稳定引用

提供给 Prompt 的短期视图
└── 更早问答摘要＋最近五轮原始问答
```

#### 11.1.2 如何提供给 Prompt

对 Prompt 提供的短期背景固定为两部分：

```text
公共短期记忆——当前会话
├── 更早问答的压缩摘要
│   └── 有效条件、关键结论、更正、待办、证据引用及来源
└── 最近五轮完整用户／最终助手问答（不足五轮则全部）
```

全部会话原文仍由 Memory 保存，以上只是输入视图。这里的“更早”指当前会话五轮窗口之前的问答，不是其他会话。完成第六轮后，第１轮纳入摘要，第２～６轮保留原文；后续按轮次滑动，不把每一轮都单独压缩再取最近五份。当前用户问题不提前算作已完成一轮。

Memory 另外管理当前有效事实、跨轮证据与本轮角色发布结果／完成状态，供一致读取与协作；它们不是第三段重复的历史背景。需要延续的早期条件和未完成事项保留在摘要中。本轮角色中间产物不混入最近五轮最终用户问答。

短期摘要随窗口滑动更新，保留覆盖轮次、来源 ID、版本及纠正记录；不覆盖原文。不盲目无限“摘要套摘要”，按需要从保留原文重新生成，过长来源可分批处理。摘要更新仍采用固定来源快照、校验和版本条件提交，在下一次 Prompt 读取时切换；未就绪或失败不删除原文、不发布缺失关键条件的视图。短期预算也必须计入完整输入，最近五轮不保证天然装得下；超过硬预算需受控等待／缩小处理，不能擅自默默压缩最新五轮。

来源是每轮瞬时记忆的必要转存，不把每个 Agent 的全部试错过程搬入公共会话；内部原文在私有范围归档。用户／最终助手消息一份追加式存储，最近五轮是查询视图，不另存重复全文。本轮识别意图不自动作为下一轮意图沿用。需要公开跨轮使用的证据取得会话级稳定引用。

事实原始消息 ID、修订版本和状态要可追溯。Agent 答案／猜测不是用户确认事实；政策属于来源证据。较早已完成问答可总结，但不覆盖会话原文。暂不照搬 EchoMind 每轮画像提取与全历史摘要向量化。长历史初期按消息 ID／时间／文本读取，确实需要时再增加语义检索。

关闭会话不自动把内容变成画像；尚需参与长期提取的短期档案必须保留到提取完成，不以窗口关闭立即删除。短期由系统统一管理并在当前咨询授权范围内共享；第一版没有 Agent 私有短期库。会话原文和元数据由 Memory 保存，工作区文件作为后端／产物引用，不增加独立黑板副本。

### 11.2 系统公共长期记忆

第一版公共长期记忆定位为系统维护的该用户画像，供获授权 Agent 读取；不是全用户共享，也不是某个角色的经验库。提取三类内容：

| 类型 | 可以提取 | 不自动提取 |
|---|---|---|
| 回答偏好 | 默认语言、简洁／详细、引用与展示偏好 | 只对“这次”有效的要求 |
| 相关长期背景 | 用户明确提供的研究方向、常用写作语言、投稿经验 | 根据问题难度猜学历、身份或水平 |
| 跨咨询持续要求 | 明确的“以后政策结论给官方出处”等要求 | 当前稿件阶段、预算、截止日期和当前未完成事项 |

政策／费用数据属于知识库证据，咨询报告属于档案，工具轨迹属于瞬时记忆；不混成画像，不保存密钥和密码。长期适用不意味着永不变化。

每条候选检查：用户原话来源是否存在、能否跨咨询适用、是否明确长期意愿或有独立用户表达支持、是否已有更正／撤销。不能把助手复述、摘要反复出现或同一消息重复采集计为多份用户证据。结果允许不更新，达到周期不是必须新增画像。

先用结构化存储，不为少量字段引入用户向量库。默认提供该用户当前有效且授权可用的画像快照，不加载全部变更备案、旧版或争议候选；不把所有会话原文当作长期背景。整个快照仍需计入 token 预算，不能跨用户泄漏。

### 11.2.1 来源链路与计数

```text
一次瞬时记忆完成
→ 由系统将必要记录转存当前会话公共短期记忆
→ 该用户 completed_instant_count 增加 1
→ 自上次成功提取后累计 N 次
→ 从对应公共短期记录提取，结合已有公共长期画像生成候选更新
→ 校验并提交有效更新／无更新决定，推进提取水位
```

多 Agent 共同完成一轮只计一次；同轮重试或重复转存按 turn_id 幂等，不多计。不同会话的该用户轮次可以累计；不要求会话结束才读取已转存轮次。N 未确定，讨论中举例的 10 不是固定配置。

即使用户要求“以后回答简短”，先在短期保留长期偏好候选，再通过此链路提取，不从瞬时工具日志直接归纳长期画像。短期档案保存必要用户原话和来源，不能只留下已随瞬时清理而失效的消息引用。

记录已成功处理的轮次范围／截止序号与提取版本，避免重复处理。空更新但完整检查成功可以推进水位；失败、取消或缺少来源不推进。多会话并发计数与候选提交需用户级原子操作；固定批次快照，来源截止后的新轮次留给下批，不丢弃新增信息。画像基准版本变更时重新校验，旧批次不能盲目覆盖新画像。

### 11.2.2 动态更新与备案

需求已确认：支持用户前后说法不同，保存来源和修订历史。以下是建议规则，不把“后说的一定覆盖”作为唯一算法。

| 情形 | 建议处理 |
|---|---|
| “以后不要简短，改为详细解释” | 明确长期更正：提议替代对应字段，旧版标 superseded |
| “这次详细一点” | 当前轮／会话覆盖，不改全局画像 |
| “平时简短，讨论代码时详细” | 按适用范围保存条件偏好，不当成矛盾 |
| 用户明确纠正背景 | 更新对应事实与来源，不同时将新旧值视为当前事实 |
| 两个同范围陈述相反且缺少更正依据 | 保留冲突候选，状态 disputed；不得无提示地认定其中一个正确，需要时澄清 |
| 新批次没有再提及旧偏好 | 不因遗漏自动删除已有效字段 |
| 要求不再使用／忘记某信息 | 撤销读取；涉及删除请求走单独删除策略，不等 N 次，也不以审计为由永久保留敏感旧值 |

在周期提取到来之前，当前明确用户要求优先于旧画像；来源仍先进入短期。不要等到长期任务运行才在当前回答中尊重最新要求。跨会话读取时也需检查待处理的明确更正／撤销候选，避免尚未到周期的新要求被旧画像遮蔽。

候选更新操作区分 `add/replace/retract/scope_change/conflict/no_change`，不能用整份新 JSON 无条件覆盖整个用户画像。每个字段保留当前版本，另有追加式变更备案。

备案至少记录：`memory_id/user_scope/key/value/scope/version/state/source_conv_ids/source_turn_ids/source_message_ids/extraction_batch_id/base_profile_revision/created_at/updated_at/operation/change_reason/supersedes`。时间、版本、身份由程序管理，不由模型伪造。状态包含 active、superseded、retracted、disputed；检索不能把旧版和冲突候选都当作有效偏好注入。

示例（设计示意，不是真实用户记忆）：

```text
v1：回答偏好=简短；用户消息 M01；曾有效
v2：回答偏好=详细；用户消息 M20“以后改成详细解释”；当前有效
变更：v2 replaces v1；v1 标 superseded，不悄悄覆盖来源
```

备案用于追溯，不要求每次加载全部版本，也不保存隐藏推理。通常记录原话引用、可读的操作原因及提取版本即可。忘记／删除时可保留最小必要操作元数据而不保留被删除内容；具体留存和备份删除政策实施前再确定。

### 11.3 与 EchoMind 的取舍

已观察到 EchoMind Python 记忆链路：Redis 最近消息与摘要、Chroma 历史摘要与画像，最终转换成背景文本；接口取最近 5 条消息供识别、背景取最近 8 条，并非最近五轮。压缩后历史正文主要是摘要，metadata 的 full_text 只留前 500 字符；每轮后台提取画像。

本项目不照搬这些消息数、跨会话默认召回、每轮画像更新和仅摘要档案。可借用读取／检索／摘要的思想，但保持范围、原文追溯与写入权限明确。此处是静态实现观察，不声称测得记忆准确率优于 EchoMind。

## 12. 建议验收场景与可观测性

以下是后续实施必须验证的场景，不是已通过的测试。

1. 两个用户／两个 Agent run 不能互读私有记录；公有范围不越过当前咨询。
2. 最近两组 tool 原文展示，较早正文有摘要，原始调用与结果 ID 保持配对。
3. 一步多个工具乱序返回、部分失败或未返，不产生孤立调用，不错误标为完成。
4. 摘要时追加新消息，新消息仍在；不要求 raw 头完全不变。
5. 旧候选晚到，不能覆盖新 projection；约束被纠正时旧摘要不能继续生效。
6. 二级压缩时 TODO 变为完成／预算减少，不能被旧状态覆盖。
7. 70% 触发不会无限排队；没有可压缩内容时不反复付费。
8. 摘要超时／取消／引用非法／无节省时，不破坏原记录；下一次请求不超硬预算。
9. 单工具结果超过模型窗口时可分段处理，明确不完整，而非直接请求失败后无上限重试。
10. 摘要数字或状态错误可发现并回到来源；周期重建不只以旧摘要为依据。
11. 本轮结束与后台读取并发时无提前清理、迟到发布或跨轮引用失效；必要转存完成后才释放。
12. 最终用户仅收到明确发布的答复／产物，不能误把内部工具指令、私有调试或密钥输出。
13. 同用户跨两个会话累计 N 个有效轮次触发一次长期提取；多 Agent、重试、重复转存不增加计数，失败不误推进水位。
14. 短期转存保留长期提取所需来源；瞬时清理后仍可核验用户原话，不加载另一用户资料。
15. 明确更正、仅本次要求、条件偏好、未决矛盾分别处理；旧画像不能压过当前明确要求。
16. 画像候选与并发批次按版本提交，不覆盖新增字段；可查替代／撤销备案，disputed 与旧版不当作有效事实。
17. 公共记忆是唯一共享数据入口：没有独立黑板副本；同次组装读取一致的公区版本，文件不重复保存全文。
18. Agent 只有私有瞬时记忆；角色只能提交自己的结果，系统合并公区事实与画像，不能跨用户读写或自行创建角色长期画像。
19. 多角色公开结果可按 turn_id 汇总，但结果发布不重复写入最终用户历史、不多次增加完成轮次计数；私有轨迹不会因取消黑板而自动公开。
20. 短期输入为当前会话历史摘要＋最近五轮原始问答；窗口滑动不丢有效条件、不加载其他会话、不重复当前输入。
21. 压缩、滑窗和结束执行不删除记忆唯一原文；私有归档保持权限，摘要可回溯来源，不为保存原文额外新增记忆层。

建议记录：组装 token／输入预算、触发原因、source cutoff、投影与状态版本、来源 ID、压缩耗时／用量、节省 token、候选接受／丢弃原因、受控等待次数、实际服务缓存指标。日志不记录密钥，不把后台摘要调用当免费，不预先声称延迟下降或缓存命中提升。

## 13. 当前边界与后续

- 已有代码的终点仍为识别 → 路由 → Agent 输入准备；本文不代表工具循环、公共记忆、压缩或工作区权限已实现。不要求实现已取消的独立黑板。
- 本次只保存设计与项目入口。没有业务代码改动、依赖安装、模型请求、索引改动或原始文件清理；项目未为本文新建 Git 仓库或提交。
- 需要后续细化：提供方实际 Schema 支持、存储后端、工具结果字节限额、输入／输出预算数值、周期配置及跨轮转存契约。
- 异步并发建议要先审阅，再形成实施计划；不因为已有讨论就立即实现整个 harness。
- v0.2 替代“独立黑板”“每个 Agent 都有长短期记忆”的旧候选；继续排除“assistant 普通文本再分类”“所有结果先调用 LLM 精简”“以会话数触发长期提取”“每轮从瞬时直接写用户画像”。

一句话原则：**Agent 只有私有瞬时，系统维护公共短期／长期，不设独立黑板；Memory 保存原文与摘要，Prompt 只读取组装；短期输入为当前会话历史摘要＋最近五轮原文；瞬时一级压缩工具正文、二级压缩状态栏，70% 异步触发并安全切换，不覆盖来源；每 N 个有效问答轮次从公共短期沉淀公共长期。**
