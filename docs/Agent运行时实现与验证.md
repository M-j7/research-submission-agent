# Agent 运行时：实现与验证

日期：2026-10-09。本文记录本次实际实现，不将 10-08 的设计稿改写成当时已完成。

## 1. 已接起来的流程

```text
接收 Request、保存用户输入、领取本轮执行权
→ 读取公共记忆快照
→ 复用现有三路意图识别、路由、角色准备
→ 每个角色建立私有 run 和工作区，执行 Agent Loop
→ 将角色正式结果发布到公共协作记录
→ 单角色直接返回；多角色交汇总 Agent 核验、融合
→ 保存唯一最终答复，再返回用户
→ 后台维护会话摘要与用户画像
```

旧 `src/submission_assistant/graph.py` 仍是识别到角色准备的预览入口。新执行入口是 `runtime/chat.py`，不是替换掉旧接口。四个专业角色和通用兜底沿用已有划分，所有角色共用 `AgentLoop`，只换角色提示词、模型和工具白名单。

Request 保存本轮身份、标识和原消息；识别、路由、公共快照与结果放在外层图状态中，而不是把所有私有轨迹塞进 Request。多角色读取同一初始公共快照，只向汇总角色提供正式结果，不暴露彼此的原始试错轨迹。

汇总结果按证据 ID 去重并继承来源。任一角色未完成的核验，会保留为未解决项，不能仅因汇总模型生成了文字就把整轮标成完整成功。角色结果不是最近五轮问答；一轮只有一个用户输入、一个最终答复。

## 2. 各部分落点

| 模块 | 本次实现 |
| --- | --- |
| `runtime/memory.py` | SQLite 原文追加、私有瞬时投影、公共会话快照、摘要版本、用户画像与来源备案 |
| `runtime/maintenance.py` | MemoryManager 所属的压缩与提取服务；不是 PromptManager 做摘要 |
| `runtime/prompt.py` | 固定前缀＋公共记忆＋当前问题/意图＋本实例轨迹＋末尾状态栏；只组装与检查预算 |
| `runtime/workspace.py` | 授权虚拟路径、私有工作区、持久化工具原文、公共证据文件、精确实例清理 |
| `runtime/skills.py` | 六份已有 Skill 的 name/中文 description 索引，正文用 read 按需披露 |
| `runtime/tools.py` | glob、grep、read、query_memory、统一 search_knowledge；Pydantic Schema 与执行前校验共用定义 |
| `runtime/provider.py` | 原生 OpenAI 兼容工具调用，普通回复文本不解析成可执行指令 |
| `runtime/loop.py` | 真正的 LangGraph 内循环、并行只读工具、预算、超时、错误配对与停止 |
| `runtime/chat.py` | 外层聊天 DAG、多角色正式结果发布、汇总与唯一最终提交 |
| `runtime/rag.py` | 查询改写→JEV 校验→双路召回→跨列表 RRF→原问题重排→父块展开 |
| `runtime/cache.py` | 版本化 RAG 缓存、TTL 随机扰动、可选 Redis 跨进程互斥与本地 TTL 降级；不缓存个性化最终答案 |

工具 Schema 约束的是调用参数。后台仍严格校验白名单、类型、额外字段和路径权限，不把“模型一定遵守 Schema”当安全边界。工具返回结构化结果，用户答复保持普通文本。

## 3. 记忆与上下文的实际策略

- 私有瞬时记忆保存本轮 assistant/tool 原生配对、执行步次和状态；公共短期是当前会话历史摘要＋最近五轮原始问答，另有正式角色结果；公共长期是用户有效画像。
- 原文不被摘要覆盖。工具正文超出呈现预算时，完整结果落持久化私有文件，模型收到可续读引用，不是静默裁剪后假装完整。
- 瞬时输入达到预算 70% 可异步压缩旧工具正文，保留最近两组完整工具调用。来源快照、投影版本检查和 run 结束取消，防止迟到摘要覆盖新状态。
- 当前状态栏是短的程序计数，Prompt 只放最新版；历史状态原文仍保存。**尚未实现自然语言状态栏的第二级模型压缩**，不能将这一设计写成已经验证的功能。
- 更早问答摘要没有成功生成时，保留未覆盖原文；超过硬预算则受控结束，不无声丢失历史。大批次记忆维护当前会拒绝过大的来源包，分批增量提取尚待补齐。
- 长期每 N 个完成轮次提取，默认 N=10；水位按完成顺序推进，避免并发会话晚完成导致漏提取。画像支持替换、撤销、争议及来源范围检查；CAS 在 SQLite 写事务内执行。
- Prompt 的 token 计数可注入真实 tokenizer；默认是保守 UTF-8 字节估算，**不是实际 token 或计费数据**。前缀组织是缓存友好设计，不代表已经测得 KV Cache 命中率。

## 4. 文件系统与存储

```text
/system/skills、templates、manuals      → resources/ 下的系统资源（只读工具）
/private/scratch                       → runtime/ 下本实例临时区
/private/tool_results                  → data/memory/blobs/ 下私有完整工具结果
/shared/conversation/*                 → data/workspaces/ 下当前用户/会话的共享文件
SQL 记忆                              → data/memory/memory.sqlite3
既有 Chroma                           → AI_Learning/chroma_ieee_submission_assistant
```

身份与实例目录名经过哈希。SQL、配置、索引不作为普通可遍历文件暴露给模型。记忆通过受控 `query_memory` 查询，不接受自由 SQL；现有知识库通过 `search_knowledge` 查询。

四类区域中，外部挂载资源只保留设计，**未接入 Google Drive/Notion 等适配器**。Agent 完成本轮后清理自身临时 runtime 子树；私有工具原文和公共结果保留，不随临时区销毁。原件、解析结果及已有索引没有迁移或重建。保留期限、容量治理和垃圾回收尚未实现。

## 5. RAG 改写与缓存

原问题始终参与召回；最多接受三个等价改写，最多两次生成尝试。JEV 未通过的候选不进入检索，判断服务失败时保留原问题与此前已通过候选。改写不得新增独立诉求、主体、条件或否定反转。

各查询执行向量/BM25 双路召回，合并排名列表做 RRF，按子块 ID 去重后用**原问题** rerank，再展开父块。部分召回失败或 reranker 失败时返回明确降级提示；整个召回不可用与“没找到政策”分开处理。

RAG 是工具内的有界异步流水线，**不是另一个已画出的完整 LangGraph RAG 子图**。沿用既有子块、父块、术语表与纯排序函数。读取时确认有 966 个父块、2737 个子块；本次没有重嵌入或修改 Chroma。

缓存键包含查询、top-k、语料/配置版本、模型与范围。不缓存错误、带降级警告的结果或用户最终答案。基础 TTL 为 300 秒并加入 ±10% 随机扰动；同一 RAG key 先用进程内锁，再用 Redis `SET NX PX` 互斥，使用 token 校验后通过 Lua 原子释放，锁租约 120 秒、等待上限 90 秒。Redis 读写或锁操作故障时回退本地 TTL／继续正常检索；Redis 不可用不改变权威结果。当前没有启动预热清单，RAG 缓存冷启动采用自然回填：首次 miss 正常检索，成功后写缓存；意图示例向量继续使用已有的版本化本地磁盘缓存，不重复写 Redis。

本机已通过 Docker 运行独立 Redis 7 容器 `submission-assistant-redis`，仅发布到 `127.0.0.1:6379`，不启用 RDB/AOF 持久化，内存上限 256 MB，淘汰策略为 `volatile-lru`；缓存数据可丢失并由查询自然回填。项目 `.env` 使用 `REDIS_URL=redis://127.0.0.1:6379/0`，Redis Python 客户端已安装到 `ieee-submission-assistant` Conda 环境。实测 PING、缓存读写和两个缓存实例间的同键互斥通过。锁等待超时后为保证可用性会继续执行查询，因此它是有界的击穿抑制，不是跨进程严格限流。尚无 Redis 高可用、持久化、分布式状态缓存、独立查询向量缓存或生产级熔断器。

## 6. 默认预算与停止

| 预算 | 基线 |
| --- | --- |
| 每角色决策步数 | 8，最后一步禁用新工具 |
| 每角色工具调用数 | 20 |
| 每角色截止时间 | 180 秒 |
| 每角色工具并发 | 2 |
| 同一请求共享决策/工具上限 | 24 / 48 |
| 同一请求共享截止时间/工具并发 | 240 秒 / 4 |
| RAG 总截止时间 | 90 秒 |
| 本地工具扫描截止时间 | 5 秒，逐段让出执行权；单次正则另有限时 |

重复调用连续两次得到相同结果后不执行第三次；累计三次非法参数/越权工具错误后结束。模型空回复、截断、拒答、超时均不标成成功。输出估算也检查累计预算，不能绕过输入前检查。

这些是**实验基线，不是质量调优结果**。共享请求尚未统一核算 RAG/JEV/Embedding/记忆维护的 token 和费用，所以不能宣称严格的全请求成本上限。同一 turn_id 已完成后返回保存的答案，不重放工具；中断后拒绝自动重放，不是已实现 checkpoint 恢复。

## 7. 运行方法

```powershell
conda activate ieee-submission-assistant
cd "C:\Users\amorous\Documents\AI_Learning\求职\投稿咨询助手项目"
python .\scripts\chat.py --demo
```

demo 使用临时目录、受控识别器和模型，不联网，不提供真实政策结论。它演示两个专业角色各调用一次工具，再由汇总角色给一份最终答复。

真实模式会调用配置服务并产生费用、保存当前会话：

```powershell
python .\scripts\chat.py --live --message "IEEE Access 摘要有哪些要求？" --user-id local-user --conversation-id ieee-test
```

加 `--no-multi-query` 可对照原查询基线；重试时显式使用相同 `--turn-id`。CLI 身份只适用于可信本地调用，**不是 Web 登录鉴权**。

继续使用项目根目录 `.env` 中的 `LLM_*`、`EMBEDDING_*`、`RERANKER_*`、`JEV_*`。可选 `AGENT_<角色英文大写>_MODEL` 覆盖角色模型；`MEMORY_PROFILE_EVERY` 调整提取周期。Redis 使用本机 Docker 容器和 `.env` 中的 `REDIS_URL`；Docker Desktop 未启动时缓存自动降级，不影响权威检索结果。没有改动已有模型密钥。

## 9. 本次实施裁定

- 无 Git 仓库：原地最小范围实施，不初始化仓库、不运行 Git worktree/commit、保留台账。代价：尚无 Git 回滚历史。
- 不使用额外实现 Agent，只有一次只读整体审查；不因用户已授权实施而擅自接人工操作或第三方资源。代价：这些集成仍待后续设计。
- 保留旧预览入口和现有索引，增加可执行入口与适配器。代价：有两种入口，使用时需区分预览和执行。
- 默认预算、JEV 改写阈值和提取周期仅作为可测基线；不把离线通过或两次探针写成质量达标。代价：还需真实样本调优与联调。
- 原始记录与持久化工具文件保留，瞬时视图结束不删除来源。代价：需后续制定存储容量与保留策略。
